## Key Architectural Decisions Made Today

### 1. Heuristics Over Meta-Orchestration
**Question:** Should LLM control its own context selection?

**Decision:** No - use heuristic-based phase detection (industry standard)

**Reasoning:**
- Cursor, Copilot, Devin, Windsurf all use heuristics
- No major player gives LLM control over prompt components
- Tools like `request_context`, `declare_phase_complete` would be novel but unproven
- Better to follow validated industry patterns

### 2. Notes in WorkStream, Not Workflow
**Question:** Where do failure clusters belong?

**Decision:** WorkStreamContext (session state), not ExecutionBrief (task plan)

**Reasoning:**
- WorkStream = persistent session state (survives pause/resume)
- ExecutionBrief = ephemeral task plan (regenerated per task)
- Failure tracking is state, not plan
- Matches industry pattern (Cursor/Devin track results in session)

### 3. Conditional Generation Over Trimming
**Question:** How to prevent context bloat?

**Decision:** Generate only needed components per phase (conditional generation)

**Reasoning:**
- Don't generate 9704 chars just to trim to 2600
- Generate ~2200 chars directly for execution phase
- Aligns with how GitHub Copilot/Cursor handle different modes
- Eliminates risk of trimming wrong content

### 4. Prescriptive Over Descriptive Directives
**Question:** How to ensure LLM generates patches?

**Decision:** Use prescriptive commands ("Call preview_patch NOW") vs descriptive policy ("patch minimally")

**Reasoning:**
- "Inspect the test" triggered investigation loops
- "Call preview_patch" is unambiguous action
- Execution phase needs clear commands, not philosophical guidance
